# Automated run-report completion — 10 November 2026

Implemented in the CapZyme-DAD checkout, based on `ef49a03`. This document
records validation completed before publication. The validation activities did
not commit, push, publish or merge changes; subsequent publication is recorded
in the repository history.

## Implementation and commands

```bash
capzyme report --analysis-dir /data/my-analysis/results
capzyme report --analysis-dir /data/my-analysis/results --output-dir /data/review/report
```

Default outputs are `report/report.html` and `report/sample_summary.tsv` beneath
the analysis directory, with structured `report_status.json`. New workflow reports
also save `analysis_context.json`, recording requests rather than execution success.
See the [CLI/report guide](run_report.md) for inputs, statuses, columns and limitations.

The independent standard-library generator is `workflow/scripts/run_report.py`.
`capzyme_cli` dispatches `report` directly; no scientific or Snakemake modules are
imported. `report_step.py` calls that same generator from the final `run_report`
rule. All RNA, sequential, genome-only and existing-BAM entry points depend on
report outputs; the report depends on the original terminal analysis targets,
including requested tracks/comparison, with no upstream consumer of reporting.
It cannot certify the subsequent Snakemake exit status and says so explicitly.

HTML uses embedded CSS, escaped data, relative URL-encoded links, readable
scrolling accounting tables and expandable detailed checks/source/output lists.
TSV IDs retain strings such as `01`; percentages name their denominators.
RNA/genome pools remain separate. Disabled normalization methods are labelled
not enabled. Missing requested outputs, failed receipts, mismatched IDs, totals,
small-record pins or normalization factors return nonzero while retaining an
informative report. Failed workflow report copies survive in `logs/failed_*`.
MultiQC stays optional/external; it is neither installed nor run.

## Read-only completed-run demonstration

The supplied completed twelve-library analysis was inspected through the existing
native SSH/Kerberos connection. Only saved records, matrix headers and filesystem
metadata were read. New demonstration reports were written to separate private
project directories, never into the original results. The final report passed
**1,083 checks**, with sample IDs `01`–`12` in historical order, separate RNA/genome
raw/RPM records, and no failed required checks. Earlier layout demonstrations were
retained; none reran a scientific stage.

Final files: HTML **266,740 bytes**, TSV **3,055 bytes**, status JSON **241,323 bytes**.
The generator took **0.341 s**; the monitored wrapper took **1.171 s**, at niceness
10, at most four CPU affinity cores and a monitored 16 GiB aggregate allowance.
Two resource samples saw **50,585,600 bytes (48.242 MiB)** peak aggregate RSS;
this is a sampled observation, not a continuous peak measurement. The output
ceiling was 1 GiB, with a 50 GiB filesystem-free floor. No limit was breached.
Filesystem availability is not a project-quota certification; no quota capacity
claim is made for this small reporting task. Original matrix/provenance/BAM/QC
sizes and mtimes were unchanged across all **76** checked artifacts. This is not
fresh original-file checksum verification.

The final demonstration reports two limitations prominently: older runs have no
saved request plan, so undiscovered historical requests cannot be certified; the
genome counter log has no cohort-total summary, so matrix headers are inspected
without reconstructing genomic counts. Saved overlap/handoff/large-file checks
remain labelled recorded. No fresh large-file hashes, read-ID joins, FASTQ/BAM
scans, count reconstruction, BigWig decoding or normalization were performed.

Private exact server/local output locations, commands, input/source pins, native
access details, monitor samples, earlier attempts and compact report copies are in
ignored `logs/run_report_2026-11-10/`, starting with `access.private.md` and
`remote.private.json`. Local copies display the HTML, but server-relative output
links need the server analysis tree or equivalent mounted layout. No research
reads, BAMs or complete count matrices were transferred to the Mac.
